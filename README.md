# Живи с Унистрой — лендинг с шапкой Унистрой

Статический сайт: `index.html`, компонент `header/`, шрифты и изображения. Сборка не требуется —
папка выкладывается на веб-сервер как есть.

Эта папка — версия первого этапа (`release_header`). При выкладке её содержимое
заменяет файлы по уже существующему адресу GitHub Pages: URL страницы менять не
нужно. Папку `release_clean` не трогать — это архив предыдущего релиза.

## Навигация в шапке

- Общее меню воспроизводит `https://unistroy.ru/` для Казани по снимку от 05.10.2026.
- По решению заказчика счётчики доступных объектов и цены убраны из всех версий
  меню, чтобы статический лендинг не показывал устаревшие данные.
- В нём сохранены исходные «Акции», «Сдать квартиру», «Дарим квартиру» и их адреса.
- Третий ряд — якорная навигация по разделам лендинга.
- Адреса, состав и порядок разделов сверены с головным сайтом. Исходные адреса
  сохранены, включая временно недоступные страницы способов покупки.
- Переключатель темы сохраняет выбранное состояние шапки в браузере пользователя.
- Телефон во всех вариантах меню постоянный: **+7 (960) 069-30-30**.
  Коллтрекинг и динамическую подмену номера на этой странице не подключать.
- Интеграция общего меню и формы обратного звонка описана в `header/README.md`.
- Результаты проверки и парные снимки: `qa/menu/report.html`. Каталог `qa/`
  предназначен для передачи разработчикам; на публичный сервер его выкладывать не нужно.
- В GitHub Pages каталог `qa/` и инструкции исключены через `_config.yml`.
  Файл `.nojekyll` не добавлять: он отключает обработку этих исключений.

## Что нужно сделать при выкладке

1. **amoCRM.** В `index.html` найдите `AMOCRM_CONFIG` (блок `<script>` внизу файла):
   - `endpoint` — URL прокси/API для приёма заявок (POST, JSON);
   - `dryRun` — поставить `false` после подключения endpoint;
   - `pipelineId`, `statusId`, `responsibleUserId` — по необходимости.
   Пока `dryRun: true` или endpoint пуст, данные подготавливаются без отправки.
   Служебные сообщения о подключении в интерфейсе отсутствуют. На localhost
   payload пишется в консоль для разработки. Подтверждение приёма заявки появляется
   только после успешного ответа подключённого API.
   Структура payload — функция `buildAmoLeadPayload`.

   Вместе с контактом передаётся `consent`: отдельные значения `personalData` и
   `marketing`, время действия в браузере `capturedAt`, подписи галочек и сведения
   о документах (URL, версия и SHA-256 PDF). Реклама необязательна; `marketing: false`
   не препятствует отправке заявки. Политика указана как информационный документ.

   **До включения отправки:** сервер должен проверять обязательное согласие,
   допустимые версии документов и типы значений, сохранять запись согласий вместе
   с идентификатором заявки/контакта и собственным временем приёма. Ответ об успехе
   нужно возвращать после сохранения заявки и записи согласий. Данные клиента
   не являются доверенным серверным журналом. Передавать контакт в рекламу можно
   только при отдельном положительном согласии; учитывать последующие отзывы.
   Хранение, обработка отзыва и подключение CRM на сервере в этот статический релиз
   не входят и пока не реализованы. Данные заявок в localStorage не сохраняются.

2. **Обратный звонок из меню.** Подключить отдельный `callbackEndpoint` или
   обработчик события, описанный в `header/README.md`. Согласовать маршрутизацию
   заявки, оператора и юридические ссылки этой формы. Одной настройки amoCRM
   основной формы недостаточно для подключения обратного звонка.

3. **Адрес сайта и ресурсы.** `og:image` и `og:url` уже содержат абсолютные адреса
   GitHub Pages. При переносе на домен Унистрой заменить их на адреса публикации.
   Проверить HTTPS, сжатие HTML/CSS/JS, кеширование, CSP и получение заявки на
   целевом сервере. Не публиковать служебный каталог `qa/`.

4. **Промоссылка.** В мобильном меню «О компании» карточка «Комфорт начинается
   здесь» содержит исходный адрес `https://google.com`. Согласовать целевой URL
   с владельцем головного сайта. Произвольная замена адреса в QA не выполнялась.

## Итоговая проверка 06.10.2026

Отчёт: `qa/final-2026-10-06/report.html`. Проверены 6 размеров экрана в двух
темах, меню, 74 расчётных сценария, формы на локальном стенде, ссылки и ресурсы.
Реальная доставка в CRM, реальный эквайринг и целевая серверная конфигурация
не проверены: эти интеграции в статическом релизе отсутствуют.

Форма принимает полный российский номер из 11 цифр. Во время отправки повторная
отправка блокируется. При выборе модели в форме расчёт в payload соответствует
этой модели; для «Пока не выбрал» расчётные поля равны `null`. При изменении
калькулятора предыдущая подпись перенесённого расчёта скрывается.

До запуска подтвердить ставки и экономические допущения калькулятора, права на
шрифты, бизнес-обещания и юридическую схему обеих форм. QA проверяет реализацию
текущих правил и не заменяет согласование этих условий.

## Примечания

- В `policy/` находятся три PDF для посетителей: политика обработки персональных
  данных, согласие на обработку и согласие на рекламу. Они получены из исходных
  Word-файлов в `../policy/` без изменения юридического текста. Внутренняя
  рекомендация по оформлению формы не публикуется. Галочка основного согласия
  сохранена до уточнения с юристами.
- Публиковать нужно файлы сайта из `release_header`, включая `header/` и `policy/`,
  исключая служебный каталог `qa/`. Ссылки
  относительные и работают как в подпапке, так и в корне сайта.
- `policy/manifest.json` содержит контрольные суммы исходных DOCX и опубликованных
  PDF. Версия PDF равна первым 16 символам SHA-256, это технический идентификатор,
  а не дата юридического утверждения. При обновлении документов синхронно менять
  PDF, manifest, `LEGAL_DOCUMENTS` и параметр `v` в ссылках формы/подвала. Старые
  версии документов сохранять на сервере вместе с журналом согласий.

- Коэффициенты калькулятора — в объекте `CONFIG` там же в `<script>`.
- Шрифты подключены локально. Обычный TT Norms Pro используется для основного текста
  и интерфейса, TT Norms Pro Expanded (200/300/500/600/700) — для display-типографики,
  крупных цифр и названий моделей. Браузер загружает только используемые начертания.
- Кодировка UTF-8, отдавать `index.html` с `Content-Type: text/html; charset=utf-8`.
